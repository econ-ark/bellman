# The build of the editor bundle

This folder holds the recipe for the files under `../../bellman_workbench/public/codemirror/`, which Bellman Workbench's page loads as the file region (model interface specification 0.3, §2.2): `bellman-workbench.js`, one script that defines `window.bellmanEditor`; `LICENSES.txt`, the license notices of the packages it is built from; and `katex/`, KaTeX's stylesheet, its fonts in the WOFF2 format and its license, which the preview of a note reads (unit N, Task 4; G-D12, nothing is fetched from a network). No file there is edited by hand; all are the output of `build.sh`.

## The sources

`src/editor.js` is the bundle's interface (its header comment documents `create`, the handle's methods and the five events); `src/bl_language.js` the stream language that colors `.bl` files, written from the patterns of the VS Code extension's grammar and presentation only, which tells a perch tag, a role tag (one of the words `setRoleWords` was given) and any other tag apart, and whose `stageName` reads the stage name from the language's syntax tree; `src/decorations.js` the decorations of the stage name, of its line's gutter elements and of the annotated lines, drawn only, which change no character of the document; `src/minimap.js` the text minimap, a strip at the editor's right edge with one mark per line, which reads the document's lines, `stageName` and the pattern `GROUP_HEAD` and changes no character of the document; `src/hidden_types.js` the rule that hides the bracket groups carrying an identity; `src/notes.js` the notes, the quoted explanations of the annotations, each drawn as a note glyph whose preview renders the explanation as Markdown with markdown-it and typesets its mathematics with KaTeX (design pass 10 §9); `src/shortcuts.js` the rule that expands the Unicode shortcuts of the extension's snippets on Tab; `src/theme.js` the editor's theme, whose every color is a custom property of `bellman_workbench/brand.css`, with the token colors of model interface specification 0.4 §5.2, the line treatments of its §5.4, the mark of the line a preview shows (its §5.8) and the wrap column. `rollup.config.mjs` bundles `src/editor.js` as one IIFE named `bellmanEditor` and gives it the version string of the CodeMirror packages. `package.json` names every package at an exact version and `package-lock.json` fixes the whole tree; `licenses.mjs` writes the notices from the lockfile and the license files under `node_modules`.

## The command

Under Node 22 and npm, in this folder:

```
NODE_EXTRA_CA_CERTS=<ca bundle> bash build.sh
```

`build.sh` runs `npm ci` (the exact versions of the lockfile, a network request unless the npm cache holds them), `npx rollup -c` (which writes `dist/bellman-workbench.js`), and `node licenses.mjs > dist/LICENSES.txt`, then copies the two files to `../../bellman_workbench/public/codemirror/`, writes `katex/` there again from `node_modules/katex/` (`dist/katex.min.css`, the WOFF2 files of `dist/fonts/`, the first format the stylesheet names, and `LICENSE`), and prints the Node version, the digests of the script, the notices, the stylesheet and the license, the number of fonts and the digest of the fonts read one after another in the order of their names. `dist/` and `node_modules/` are not tracked. The variable `NODE_EXTRA_CA_CERTS` is needed only where npm reaches the registry through a proxy with its own certificate.
