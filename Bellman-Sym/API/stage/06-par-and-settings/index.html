    Parameters and settings¶

    Summary

    stage.par answers a table of the parameters of a stage, the derived parameters the stage defines from them standing after the declared ones, and stage.settings a table of its settings; each entry is read by the name the file declares, stage.par["ρ"] and stage.settings["n_a"], and neither table can be edited. A parameter is part of the economic problem and is declared in the stage file; a setting is a numerical choice of a method, declared with its set in the methods file and valued by configuration. Every listing is printed by the package from applications/portfolio-choice/declaration/stages/cons/cons.bl, calibrated by applications/portfolio-choice/declaration/calibration/portfolio.yml, configured by applications/portfolio-choice/declaration/settings/cons.yml, and methodized by applications/portfolio-choice/declaration/stages/cons/methods.bl, the methods file beside the stage file, whose declarations fill the settings table's set column and whose entries fill its last three columns: the place at which each setting is read, the method there and, where the setting is a bound or a count of that place's grid, the grid's kind. The listings of §1.1 read instead the perfect-foresight stage file, applications/consumption-perfect-foresight-crra/declaration/stages/perfect_foresight/perfect_foresight.bl, which defines three derived parameters, calibrated by applications/consumption-perfect-foresight-crra/declaration/calibration/perfect_foresight.yml.

    Relationship with other documents

    Builds on — The stage: the object stage below; The binding verbs: calibrate and configure, which bind the values these tables read. Used by — Methods and places: the methods that read the settings. See also — API §2.4: every path of the stage object in one table; Methodization §4: the declaration of a setting and the settings file.

    Parameters are the declared constants of the model, such as the risk aversion ρ, each declared in the stage file on a set and given a value by calibration; change one and the economic problem changes. Settings are the numerical choices of the methods, such as the bounds and the count of a grid, each declared in the methods file on a set and given a value by configuration; none of them is an assertion of the model. The two tables are queries: each reads the one place the stage holds what it answers, and neither keeps a copy.

    from bellman.stage import elaborate_stage, load_stage

stage = elaborate_stage(load_stage("applications/portfolio-choice/declaration/stages/cons/cons.bl"))

    1 The parameters¶

    stage.par answers one row per declared parameter, with the set it is declared on, its value or, before calibration, the word unbound, and the description the file gives, and then one row per derived parameter (§1.1). stage.par["ρ"] answers the record of one parameter, keyed by its name as the file declares it, which prints on one line; its value is the number the calibration binds. list() answers the rows, a record that prints as the table, and view() the table as text. Since calibrate binds the stage it is called on, calibrated below is stage itself, now with its parameter's value:

    print(stage.par)
calibrated = stage.calibrate("applications/portfolio-choice/declaration/calibration/portfolio.yml")
print(calibrated.par)
print(calibrated.par["ρ"])
print(calibrated.par["ρ"].value, calibrated is stage)

    The record is read from the parameter's declaration in the stage file and from the value calibration binds. The key is the name the file declares, and no other spelling is a key:

    try:
    stage.par["rho"]
except KeyError as refusal:
    print(refusal)

    1.1 Derived parameters¶

    A derived parameter is a constant of the stage that a definition without arguments writes from the stage's parameters, such as human wealth h := 1/(1 - Γ/R); Equation parsing rules §2 gives the form, what its definition may read and the order in which the definitions are evaluated. stage.par lists the derived parameters after the declared ones, in file order, each with its definition in the column set and the description the file gives. Before calibration the value of a derived parameter is unbound. After calibration its value is its definition evaluated at the calibration values, computed each time the table is asked for and stored nowhere. The record of one derived parameter prints its definition after :=. The consumption stage file defines no derived parameter, so the listings of this section read the perfect-foresight stage file, which defines three from its four parameters: the return patience factor q, human wealth h and the natural borrowing limit L. A methods file may define a derived parameter as well, as the methods file beside that stage file defines the marginal propensity to consume κ := 1 - q (The definitions table §3). A definition in an addition, a methods file read with the stage file (The binding verbs §3), is read as the stage file's own, and it leaves the table when the addition is removed.

    derived = elaborate_stage(load_stage(
    "applications/consumption-perfect-foresight-crra/declaration/stages/perfect_foresight/perfect_foresight.bl"))
print(derived.par)
derived.calibrate(
    "applications/consumption-perfect-foresight-crra/declaration/calibration/perfect_foresight.yml")
print(derived.par)
print(derived.par["h"])

    The calibration supplies no value for a derived parameter, since its definition gives the value. A calibration source that names a derived parameter is refused under derived-parameter, at the definition, and the refused binding leaves the stage as it was; the calibration the stage keeps holds the declared parameters alone. A definition that has no finite real value at the calibration values, such as one that divides by zero there, is refused under the same rule, at that definition (Refusals):

    from bellman.refusals import ConstructionError

try:
    derived.calibrate({"calibration": {"β": 0.9615384615384616, "ρ": 2.0, "R": 1.04, "Γ": 1.02, "h": 50.0}})
except ConstructionError as refusal:
    print(refusal)
print(derived.par["h"])

    2 The settings¶

    stage.settings answers one row per setting, with the setting's name, the set the methods file declares it on, its configured value or the word unbound, the place at which it is read, the method typed there and, where the setting is a bound or a count of a factor of that place's grid, the grid's kind. The settings the methods file declares come first, in declaration order; a key of the settings file that no declaration names follows, with its value and the other columns empty, since it binds nothing (the last listing of this section). A method reads a setting by its name: here the grid of the representation at the decision builder's Evaluation, cntn_to_dcsn.evaluate.grid : !Cartesian(m_d=(m_min, m_max, n_m)), reads n_m, m_min and m_max as the count and the bounds of its grid of resources, and the grid of the endogenous grid method on the policy builder, grid : !Cartesian(a=(a_min, a_max, n_a)), reads n_a, a_min and a_max as its grid of savings (Methodization §3.2). stage.settings["n_m"] answers the record of one setting, and its value is the configured value.

    specified = (calibrated.methodize("applications/portfolio-choice/declaration/stages/cons/methods.bl")
             .configure("applications/portfolio-choice/declaration/settings/cons.yml"))
print(specified.settings)
print(specified.settings["n_m"])
print(specified.settings["n_m"].value)

    bare = elaborate_stage(load_stage("applications/portfolio-choice/declaration/stages/cons/cons.bl"))

    Before configuration a declared setting stands in the table with the value unbound, as a parameter does before calibration, with the place that reads it; configure refuses a value outside the declared set, under setting-outside-set, and a declared setting that neither the settings file nor an earlier configuration of the version values, under setting-unvalued; a later configuration keeps the values bound before and replaces those it names again (The binding verbs §3; Refusals). The listing reads a second elaboration of the stage file with its methods file, since the verbs bind the stage they are called on and stage above is configured already:

    methodized = elaborate_stage(load_stage("applications/portfolio-choice/declaration/stages/cons/cons.bl",
                                        ["applications/portfolio-choice/declaration/stages/cons/methods.bl"]))
print(methodized.settings)

    A settings file may hold the values of other stages of the application as well, so a stage can be given values that none of its declarations names. configure binds such a value, and stage.settings lists it after the declared settings, with no set and no place that reads it, which is where a misspelled key shows. A second configuration adds its values to those bound before, so the consumption stage configured by its own settings file and then by the settings file of the portfolio stage, applications/portfolio-choice/declaration/settings/port.yml, lists that file's keys, among them n_k, n_Ψ_nodes and n_θ_nodes, the grid and quadrature sizes of the portfolio stage:

    methodized.configure("applications/portfolio-choice/declaration/settings/cons.yml")
print(methodized.configure("applications/portfolio-choice/declaration/settings/port.yml").settings)

    3 One value by its name¶

    Each table also answers one value alone, read by its name as an attribute: calibrated.par.ρ answers the number calibrated.par["ρ"].value holds and specified.settings.n_a the configured value of n_a, except that a parameter or a setting whose name is one of the table's own attributes, such as list, view or values, is read by its key alone.

    print(calibrated.par.ρ)
print(specified.settings.n_a)
