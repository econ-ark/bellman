    Refusals¶

    Summary

    A stage file the package cannot read is refused, and so is a method target that names no place of a stage and a compilation the stage does not support. Every refusal says four things: where it is, what stands there, why it cannot be read, and what to write instead. This page lists every rule the package refuses under, each with the smallest example that breaks it and the refusal that example provokes. Every listing below is printed from the package, so what you read here is what your own session prints.

    Relationship with other documents

    Builds on — Stage tutorial: the file whose rules these are, written line by line. Used by — The stage: the object a file becomes once it passes them.

    A refusal of the file is raised when the file is read: elaboration returns a stage or refuses the file. A refusal is held rather than raised only where the construction builds no graph for a form the file writes: the stage then holds a refusal under not-constructed in place of that graph, as it does for the forward builders graph where a shock's distribution names a family outside the table of Shock distributions. A method target is refused when methodize binds it, a setting's value when configure reads it, and a compilation when compile_kernel() is asked for it. Each refusal carries the rule it names as a field, so an editor or a script reads the rule rather than the sentence.

    1 The four parts¶

    Take the consumption stage and write ] where a side of a block's header closes with ). The parser stops at that character, and the refusal reads:

    from bellman.refusal_examples import EXAMPLES
from bellman.refusal_catalogue import refusal_of

print(refusal_of(EXAMPLES["syntax"]))

    cons.bl:17:40: the file writes `]` here, and the language admits `)` or `,` at this place
    [id=dcsn_to_cntn, (m_d, c : !ctrl @ ℝ₊₊] : !dcsn -> (a : Xa) : !cntn] {
                                           ^
a side of a block header: a side is parenthesized in general; a single coordinate may stand bare (V : !dcsn -> …) (rule syntax)

    Where is the file, the line and the column, which leads every refusal, as an editor and a compiler both print it. What is the line of the file with a mark under the column. Why is what the file writes there and the forms the language admits at that place, in the spellings you write them in. What to write is the sentence the grammar keeps for that place, given where the position falls — here inside the side of a block header.

    A word the vocabulary does not hold is refused in the same four parts, at the word itself:

    from bellman.refusal_examples import Example
from bellman.refusal_catalogue import refusal_of

print(refusal_of(Example(
    rule="syntax", address=None, words=(),
    text="@stage: t\n[id=b, (x : ℝ) : !contrl -> (y : ℝ) : !dcsn] {\n    y = x\n}\n")))

    t.bl:2:18: the file writes `!contrl` here, which is no word-type of the language
    [id=b, (x : ℝ) : !contrl -> (y : ℝ) : !dcsn] {
                     ^
the word-types are !arvl, !cntn, !ctrl, !dcsn, !shck, !state, !vlu (rule syntax)

    2 The three vocabularies of rules¶

    The package refuses under three closed vocabularies. The rules of graph construction are claims about the authored file: that it names itself once, that every name it writes is declared where it is used, that a forward block's header lists every field its lines read and a backward block's the value fields its lines read, with the controls at which they are read. The rules of the identity table are the rules by which the string written after on: in a methods file is read: which places a target may name and how each is spelled. The rules of the Bellman factory are claims about a model's files and the dictionaries made from them: the recipe, its source files and its fills, the trellis file, the records, the joins of a period, and a file given by its path to load_stage or to a binding verb, which is read as one YAML mapping with each key written once; each refusal names the file or the address, what stands there, why it is refused and what to write.

    A rule is written once, in the package, and a refusal names it. The three vocabularies are:

    from bellman.refusals import FACTORY_RULES, RULES, TARGET_RULES

for vocabulary, rules in (("graph construction", RULES), ("the identity table", TARGET_RULES),
                          ("the Bellman factory", FACTORY_RULES)):
    print(vocabulary)
    print("\n".join("  " + rule for rule in rules))

    The table gives each rule of graph construction: written, the rule's name as a refusal closes with it, (rule X), or ; rule X) after the address the refusal names; claim, what the rule requires of a stage file, in the words of the package; denotes, a dash, since a rule is a claim about the file and not an object of the Bellman calculus; and read from, the module under packages/bellman/bellman/, its table and the key.

    rule written claim denotes read from
    syntax (rule syntax) The file is written in the forms the grammar admits, and every !-marked word is one of the vocabulary. It is the first rule a file meets: the refusal is raised where the parser or the lowering stops, and names the forms admitted at that place. — refusals.py, RULES, "syntax"
    stage-name (rule stage-name) The file names itself once: exactly one @stage line, with a name. — refusals.py, RULES, "stage-name"
    declared-once (rule declared-once) Each name, block id, statement id, and law is written once. — refusals.py, RULES, "declared-once"
    defined-once (rule defined-once) Within one block, an operative equation defines each name-sided left side once. A documentary line (!doc) defines none. — refusals.py, RULES, "defined-once"
    one-name-one-meaning (rule one-name-one-meaning) A name is a field, a function, a named space, a shock, or a parameter — one of them — and is not the name of a numerical operator. — refusals.py, RULES, "one-name-one-meaning"
    parameter-or-field (rule parameter-or-field) A top-level scalar declaration is a parameter; only a shock is both declared at the top level and listed on the side of a block. — refusals.py, RULES, "parameter-or-field"
    field-perch (rule field-perch) Every listed field has one perch, fixed by its side's perch word, its mark, or its role, and the three must agree. — refusals.py, RULES, "field-perch"
    name-in-scope (rule name-in-scope) Every name a statement or a definition body mentions is declared where the statement stands. — refusals.py, RULES, "name-in-scope"
    family-selection (rule family-selection) A selection takes a coordinate of a declared family by a key the family admits: a label of its finite set, a position counted from one on a fixed product, or a name declared within the finite integer or label index set of a collection declared on a set of functions. — refusals.py, RULES, "family-selection"
    well-typed (rule well-typed) Every operation of a line, a function body or a declared set reads values of the kinds it takes: arithmetic, an ordered comparison and the bounds of an interval read numbers, and a label is no number; a function is applied to as many arguments as it declares, each of the kind it declares; Inv inverts one function; the two sides of a line are of one kind, and its left side names one field for each result of its right side. — refusals.py, RULES, "well-typed"
    divisor-nonzero (rule divisor-nonzero) A divisor the file writes as a number is not zero: a division by a written zero is defined at no point (the definedness conditions of the fold). — refusals.py, RULES, "divisor-nonzero"
    shock-observed (rule shock-observed) A statement's perch has observed every shock the statement's right side depends on; otherwise the statement asks for an expectation. — refusals.py, RULES, "shock-observed"
    shock-reintroduced (rule shock-reintroduced) A backward function does not read a shock again beside a term whose expectation has integrated it. — refusals.py, RULES, "shock-reintroduced"
    forward-composite (rule forward-composite) The fields a statement's right side mentions are at the left side's perch, before it, or forward of it along the stage's transitions. — refusals.py, RULES, "forward-composite"
    transition-without-expectation (rule transition-without-expectation) A transition block's statements define the state transition g and contain no expectation: the forward builder is the push-forward of a measure through g, and integration over a shock belongs to a value block (Operators and builders, §"Forward operators"). — refusals.py, RULES, "transition-without-expectation"
    one-implicit-statement (rule one-implicit-statement) A block has at most one implicit statement for each output field. — refusals.py, RULES, "one-implicit-statement"
    definition-order (rule definition-order) The function definitions have a dependency order, and each applies a defined function. — refusals.py, RULES, "definition-order"
    derivative-one-name (rule derivative-one-name) A derivative names one formal argument, not several arguments at once. — refusals.py, RULES, "derivative-one-name"
    derivative-scalar-coordinate (rule derivative-scalar-coordinate) The one formal argument a derivative names is scalar, not product-valued. — refusals.py, RULES, "derivative-scalar-coordinate"
    stage-boundary (rule stage-boundary) Every field is produced and consumed: a block writes it or the stage receives it, and a block reads it or the stage delivers it. — refusals.py, RULES, "stage-boundary"
    output-defined (rule output-defined) Every required block output has an equation. — refusals.py, RULES, "output-defined"
    grid-line-consistency (rule grid-line-consistency) A grid line, a line that writes a decision state under the continuation mark (m_d[>] = a + c[>]), agrees with the law of motion solved for that state at the candidates: its right side and the law of motion so solved reduce to one expression, every function read as an opaque symbol. — refusals.py, RULES, "grid-line-consistency"
    identity-collision (rule identity-collision) No authored name collides with the spelling of an identity: a name containing the colon that separates its segments, or a name equal to one of the words a reader tests for in the last segment — result, declared, merged. — refusals.py, RULES, "identity-collision"
    readable-form (rule readable-form) The item is a form the construction rules read. — refusals.py, RULES, "readable-form"
    multiplier-declaration (rule multiplier-declaration) A multiplier is declared inside the block whose continuation grid it extends, once, marked [>], with one declared set and one bound after ⟂ that names continuation states, multipliers of the block, parameters, numbers or inf. — refusals.py, RULES, "multiplier-declaration"
    set-mismatch (rule set-mismatch) A field produced on one declared set and consumed on another is declared with sets whose inclusion holds; otherwise the stage declares the inclusion through the control's feasible set. — refusals.py, RULES, "set-mismatch"
    category-codes (rule category-codes) A set marked !categories is a nonempty range of integers written as a comprehension over ℤ or ℕ, whose annotation gives each member one category name and each name one member. The marker is written only on a top-level named set, and a field declared on a set with category codes names that set at every site that names a set. — refusals.py, RULES, "category-codes"
    value-input-role (rule value-input-role) A statement of a backward block reads values or marginal values, not both: its kernel acts on one role and its output has that role. — refusals.py, RULES, "value-input-role"
    marginal-role-retired (rule marginal-role-retired) A header lists value fields and the controls at which its lines are read, and no marginal value: a role word the language no longer holds is refused with a sentence naming the derivative term D_{a}V[>], by which a line reads the derivative of a value. — refusals.py, RULES, "marginal-role-retired"
    derivative-coordinate (rule derivative-coordinate) The subscript of a derivative term names a state coordinate of the perch at which the value is read, written without its mark, and no discrete coordinate; the refusal names the perch's coordinates. — refusals.py, RULES, "derivative-coordinate"
    signature-complete (rule signature-complete) A forward block's header lists every field its lines read that no earlier line of the block defines. A backward block's header lists the value fields its lines read and the controls at which they are read, but no state; a state of its output perch is a coordinate. A value field a backward header lists and no line of the block reads is admitted: it is left out of the block's builder and recorded as a diagnostic, unread-input, in place of a refusal. — refusals.py, RULES, "signature-complete"
    header-coordinate (rule header-coordinate) A backward block's header lists the value fields it reads and writes and the controls at which its lines are read, and no state: a state of the perch at which its output stands is a coordinate of the output function, and a state of its input perch is reached through the law of motion. — refusals.py, RULES, "header-coordinate"
    input-perch-state (rule input-perch-state) A backward line reads a state of its input or a later perch only through the law of motion. A direct read is refused, including in a relation or a condition after ⟂. A read under the expectation over the edge's shock and continuation-state indexing on a policy candidate line are admitted. — refusals.py, RULES, "input-perch-state"
    kernel-form (rule kernel-form) A kernel that compile_kernel writes as a Python function is retained arithmetic and calls to closed-form functions; a symbolic derivative has no compile rule. The function takes the values of the parameters it reads as arguments, so a symbolic version compiles too and answers no values, parameter_values None. — refusals.py, RULES, "kernel-form"
    method-option-value (rule method-option-value) Every configured method option has the type its public method row names. — refusals.py, RULES, "method-option-value"
    kernel-target (rule kernel-target) kernel and compile read a primitive operator box, and compile one whose kernel is g or G. — refusals.py, RULES, "kernel-target"
    distribution-dependency (rule distribution-dependency) The distribution declarations read one another without a cycle, and a declaration does not read its own subject. — refusals.py, RULES, "distribution-dependency"
    distribution-edge (rule distribution-edge) The shocks of connected declarations are drawn on the edge of one forward builder. — refusals.py, RULES, "distribution-edge"
    distribution-domain (rule distribution-domain) A declaration's family parameters lie in the family's domain: matched dimensions, a symmetric positive semidefinite covariance, nonnegative variances and deviations, finite endpoints in order, positive scales, and real arguments that have a number. — refusals.py, RULES, "distribution-domain"
    conditional-not-declared (rule conditional-not-declared) The conditional distribution an expectation needs is a declared conditional, a product of them, or a marginal or conditional of a joint normal declaration whose conditioning block is positive definite. — refusals.py, RULES, "conditional-not-declared"
    branch-form (rule branch-form) A branching block holds one labeled nested block per label and nothing else, at least two, in the forward block from the decision perch to the continuation perch, whose own output side is empty; a nested block has an empty input side and writes continuation fields. — refusals.py, RULES, "branch-form"
    branch-labels (rule branch-labels) The nested blocks carry the labels of the block's label coordinate, a control or a shock with its law, whose set is a finite set of at least two labels, each once and in the set's order. — refusals.py, RULES, "branch-labels"
    branch-tuple-mismatch (rule branch-tuple-mismatch) The value line selects by one tuple indexed by the label coordinate, one entry per label, and the policy maximizes over the same tuple in the same order; a branch a shock selects is read under the expectation over the shock alone. — refusals.py, RULES, "branch-tuple-mismatch"
    branch-value-position (rule branch-value-position) A continuation value stands at one position of the selection tuples, the position of the branch on whose fields it is a function. — refusals.py, RULES, "branch-value-position"
    branch-law (rule branch-law) The law of a label shock gives one probability to each label in the order of the labels, Categorical((p₁, …, pₙ)) or Bernoulli(p) over two. — refusals.py, RULES, "branch-law"
    not-constructed (rule not-constructed) The item is a form of the language the construction does not read (NotConstructed). — refusals.py, RULES, "not-constructed"
    block-header-mismatch (rule block-header-mismatch) A method block's header matches the builder the methods file opens with it: the block joins the builder's perches, writes the builder's outputs, and reads the builder's inputs or inputs its header declares with a set and a role. — refusals.py, RULES, "block-header-mismatch"
    block-name-undefined (rule block-name-undefined) A line of a method block calls a function the stage file or the block file defines, or a primitive function of the language. — refusals.py, RULES, "block-name-undefined"

    3 The catalogue¶

    Every rule with the four parts of its refusal, provoked from the smallest example the package keeps for it. The example of each rule is the text the refusal test provokes, so a rule that changes is read here and in the test at once.

    from bellman.refusal_catalogue import catalogue

print(catalogue())

    syntax  (graph construction)
  where  cons.bl, line 17, column 40
  what
    [id=dcsn_to_cntn, (m_d, c : !ctrl @ ℝ₊₊] : !dcsn -> (a : Xa) : !cntn] {
                                           ^
  why    the file writes `]` here, and the language admits `)` or `,` at this place
  write  a side of a block header: a side is parenthesized in general; a single coordinate may stand bare (V : !dcsn -> …)

stage-name  (graph construction)
  where  t.bl, line 2, column 1 (address '2')
  what
    @stage: two
    ^
  why    2 '@stage' lines name the stage: 'one' at t.bl:1:1 (term address '1'), 'two' at t.bl:2:1 (term address '2'); a stage file has exactly one, so delete all but the line that names it

declared-once  (graph construction)
  where  t.bl, line 5, column 5 (address 'b.3')
  what
        y = u + z :: [!node]
        ^
  why    an authored node requires a nonempty explicit id; write an id before the mark, `:: [id=<name>, !node]`

defined-once  (graph construction)
  where  t.bl, line 4, column 5 (address 'b.second')
  what
        W = 2*V[>] :: [id=second, !node]
        ^
  why    block 'b' already defines W at t.bl:3:5 (term address 'b.first'), and this operative equation defines it again; an operative left side is defined once within a block
  write  Remove one definition, give one result another name, or mark a line that only documents the model `!doc`.

one-name-one-meaning  (graph construction)
  where  t.bl, line 3, column 1 (address 'b')
  what
    [id=b, (x : ℝ) : !dcsn -> (y : ℝ) : !dcsn] {
    ^
  why    'y' is a field, first listed here, and a function, defined at t.bl:2:1 (term address '2'); a name has one meaning in a stage

parameter-or-field  (graph construction)
  where  t.bl, line 2, column 1 (address '2')
  what
    c : ℝ₊ @ !ctrl
    ^
  why    the top-level declaration of 'c' carries the role word for 'control', but no block header lists 'c': a role belongs to a field, and a field is a name a block reads or writes, while a top-level declaration that no header lists is a parameter, a number calibration binds. List 'c' on a side of the block that uses it, or drop the role word and leave it a parameter

field-perch  (graph construction)
  where  t.bl, line 2, column 1 (address 'b')
  what
    [id=b, (V[>] : ℝ @ !vlu) : !dcsn -> (W : ℝ) : !dcsn] {
    ^
  why    the mark on V[>] places the field at the cntn perch, but the input side of block 'b' is marked `: !dcsn`; a mark agrees with its side's perch word (D06)

name-in-scope  (graph construction)
  where  t.bl, line 3, column 5 (address 'b.1')
  what
        y = q
        ^
  why    the line mentions q, which the stage does not declare: it is no field of the stage, no line of block 'b' above it defines it, and it is no parameter, shock, named space, or function. Declare it, or write one of the names in scope here: x, y

family-selection  (graph construction)
  where  t.bl, line 3, column 5 (address 'b.1')
  what
        y = (a, b)[q]
        ^
  why    the selection (a, b)[q] selects by 'q', which the stage does not declare; a key requires a finite set of 2 members

well-typed  (graph construction)
  where  t.bl, line 4, column 5 (address 'b.1')
  what

    The example of recipe-shape above is a recipe with no stages mapping. A recipe names every file it reads by its path from its own folder, the trellis file under trellis: and each stage's file under stage: in the stage's entry, and nothing is read in place of a path it does not write. The same rule therefore refuses the example registry's recipe without its trellis: line, and without the stage: line of its one entry, although trellis.yml and stages/two_nodes/two_nodes.bl stand in the registry:

    from bellman.refusal_examples import EXAMPLES
from bellman.refusal_catalogue import refusal_of

for name in ("recipe-names-no-trellis-file", "entry-names-no-stage-file"):
    print(refusal_of(EXAMPLES[name]))

    registry/spec.yml: address 'trellis': the recipe names no trellis file; write `trellis: trellis.yml`, the path from this folder (rule recipe-shape)
registry/spec.yml: address 'stages.two_nodes': the entry `stages.two_nodes` names no stage file; write `stage: stages/two_nodes/two_nodes.bl`, the path from this folder (rule recipe-shape)
