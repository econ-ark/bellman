    Method types¶

    Summary

    A method type is a numerical method that a methods file can attach to a place of a stage, such as !egm or !gauss-hermite. The table lists every method type the package defines, one row each: the line a methods file writes, the places at which the method may be bound, the settings it reads, the object of the Bellman calculus it realizes, and the line of the package that defines it. The table is printed from the package's method table, and a methods file that names a method type absent from it is refused.

    Relationship with other documents

    Builds on — Methodization: how a methods file attaches a method to a place of a stage and supplies its settings. Formal account — Methods: a numerical method as distinct from the operation it approximates; Operators: the operations the methods realize. See also — Expression forms: the forms a stage file writes, among them the operators E, argmax and solve at which a method may be bound; Refusals: the rules method-attachment and method-option-value.

    1 Reading the table¶

    Each row is one method type. written is the line of an entry of a methods file that names it, the tag after method:.

    bound at lists the kinds of place the method type admits, in the words of the method table:

    • builder, a whole builder, named by the id of its block, such as policy or cntn_to_dcsn;
    • node, a line marked !node, and statement, any other line with an id, both named <block id>.<line id>;
    • definition, a function the stage file defines, named as the file writes it, such as 𝑢;
    • boundary, the representation of a value function that a backward builder delivers where no line of the stage writes one;
    • operator and a head, one occurrence of that operator in a line, named by <block id>.<line id>.<head>; the operator's stage-wide name, such as E_Ψ_θ, names every occurrence of it in the stage at once, and one entry then binds them all; the heads evaluate and upper_env name places a methods file reaches by their addresses and have no row on Expression forms, although applications/retirement-choice/declaration/stages/worker_cons/worker_cons.bl writes upper_env(w[>], c[>], v[>]) as a call.

    options lists the settings the method reads, each with the kind of value it takes. An entry gives them under settings:; it must give every setting marked required, and it may give the others.

    takes a block says whether an entry of the method may name a block file under block:, whose block the method binds on the builder on: names (Methodization §4.1). derivatives it evaluates says, for a representation method, which derivatives of the represented function the representation evaluates: a block of a later stage that reads the derivative of the value by the term D_{a}V[>] is served by the representation alone where no derivative line states that derivative, and the stage that reads it checks nothing against this column (Trellises §2.1). The column is information about the representation; a derivative line bound with !marginals and a representation bound on the line's id are the other two ways the derivative of a value is evaluated (Methodization §4.1). condition names the condition under which the method's construction reaches the stage file's declared line, with its sentence; stage.obligations() lists it under that name, and nothing checks it.

    denotes links to the section of Appendix E.3 that defines the object the method realizes. That object is the one E.3 defines for the first operator in the row's bound at cell, so a method bound at two operators links only the section of the first of them. A method bound at no operator, such as !deterministic, !histogram or !identity, is bound on a whole builder; the method table names no operator for it, so its row links no section and shows a dash; E.3 defines the backward builders in §2 and the forward builders in §3. A method realizes its object through its handler, the routine that carries the method out, and an adapter, which converts the stage's objects into the routine's representation and converts its results back.

    defined in links to the line of packages/bellman/bellman/stage/method_table.py in the repository econ-ark/bellman that defines the method type's row of METHOD_TYPES; the module's docstring names this page in return. read from names the module under packages/bellman/bellman/, the table and the key.

    A methods file that names a tag absent from the table is refused, and so is an entry that places a method at a kind of place its row does not admit, omits a required setting, or writes a setting the row does not name without naming a handler that reads it; each refusal is under the rule method-attachment of Refusals. Configuration checks the values of the settings, and a value of the wrong kind is refused under the rule method-option-value.

    Grids and the model's sets

    The settings orders and bounds describe a numerical grid: the number of points and the interval, coordinate by coordinate, at which a function is computed and between which it is interpolated. Changing them changes the approximation and leaves the model as it was. A finite set of alternatives the household chooses from is part of the model and is declared in the stage file.
