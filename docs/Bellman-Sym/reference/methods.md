# Method types

> [!summary]
> A **method type** is a numerical method that a methods file can attach to a place of a stage, such as `!egm` or `!gauss-hermite`. The table lists every method type the package defines, one row each: the line a methods file writes, the places at which the method may be bound, the settings it reads, the object of the [Bellman calculus](../../wiki/bellman_calculus.md) it realizes, and the line of the package that defines it. The table is printed from the package's method table, and a methods file that names a method type absent from it is refused.

> [!info]- Relationship with other documents
> **Builds on** — [Methodization](../04-methodization.md): how a methods file attaches a method to a place of a stage and supplies its settings.
> **Formal account** — [Methods](../../bellman-calculus/06-Methods.md): a numerical method as distinct from the operation it approximates; [Operators](../../bellman-calculus/catalogues/operators.md): the operations the methods realize.
> **See also** — [Expression forms](forms.md): the forms a stage file writes, among them the operators `E`, `argmax` and `solve` at which a method may be bound; [Refusals](refusals.md): the rules `method-attachment` and `method-option-value`.

## 1 Reading the table

Each row is one method type. **written** is the line of an entry of a methods file that names it, the tag after `method:`.

**bound at** lists the kinds of place the method type admits, in the words of the method table:

- *builder*, a whole [builder](../../wiki/builder.md), named by the id of its [block](symbols-conventions.md#5-equations-and-nodes), such as `policy` or `cntn_to_dcsn`;
- *node*, a line marked `!node`, and *statement*, any other line with an id, both named `<block id>.<line id>`;
- *definition*, a function the stage file defines, named as the file writes it, such as `𝑢`;
- *operator* and a head, one occurrence of that operator in a line, named by `<block id>.<line id>.<head>`; the operator's stage-wide name, such as `E_Ψ_θ`, names every occurrence of it in the stage at once, and one entry then binds them all; the heads `evaluate` and `upper_env` name places a methods file reaches by their addresses and have no row on [Expression forms](forms.md), although `applications/retirement-choice/declaration/stages/worker_cons/worker_cons.bl` writes `upper_env(w[>], c[>], v[>])` as a call. The operator `evaluate` also names the [Evaluation](operations.md#evaluation) that closes the policy builder or a backward value builder, where a representation of what the builder writes is bound: `policy.evaluate` for the policy function, and `<block id>.evaluate.value` and `<block id>.evaluate.marginal` for the value function a [backward builder](../../wiki/backward_builder.md) writes and the derivative of it that a derivative line states ([Methodization](../04-methodization.md) §2).

**options** lists the [settings](../../wiki/settings.md) the method reads, each with the kind of value it takes. An entry gives them under `settings:`; it must give every setting marked *required*, and it may give the others, save that a representation at the policy builder's Evaluation where `!egm` stands writes no grid and one at an authored `evaluate(knots, values, x)` needs none ([Methodization](../04-methodization.md) §3). A method that takes a grid names it by the setting `grid`, whose value is the grid's kind written as a tag, such as `grid: !Cartesian`; the cell then lists, beside each kind of grid, the fields that kind admits as further settings of the entry, `orders` and `bounds` for `!Cartesian` among them. The grid of a representation, `!Linear` or `!pchip`, lies in the coordinates of the represented function, and the exogenous grid of savings of `!egm` in the states of the continuation perch ([Methodization](../04-methodization.md) §3).

**takes a block** says whether an entry of the method may name a block file under `block:`, whose block the method binds on the builder `on:` names ([Methodization](../04-methodization.md) §4.1). **derivatives it evaluates** says, for a representation method, which derivatives of the represented function the representation evaluates: a block of a later stage that reads the derivative of the value by the term `D_{a}V[>]` is served by the representation alone where no derivative line states that derivative, and the stage that reads it checks nothing against this column ([Trellises](../07-trellis.md) §2.1). The column is information about the representation; a derivative line, in the stage file or bound with `!marginals`, whose values the representation at the builder's Evaluation stores, is the other way the derivative of a value is evaluated, and the methods file names that representation `<block id>.evaluate.marginal` or `<block id>.evaluate.value` ([Methodization](../04-methodization.md) §4.1). **condition** names the condition under which the method's construction reaches the stage file's declared line, with its sentence; `stage.obligations()` lists it under that name, and nothing checks it.

**denotes** links to the section of [Appendix E.3](../../bellman-calculus/catalogues/operators.md) that defines the object the method realizes. That object is the one E.3 defines for the first operator in the row's **bound at** cell, so a method bound at two operators links only the section of the first of them. A method bound at no operator, such as `!deterministic`, `!histogram` or `!identity`, is bound on a whole builder; the method table names no operator for it, so its row links no section and shows a dash; E.3 defines the backward builders in [§2](../../bellman-calculus/catalogues/operators.md#backward-builders) and the forward builders in [§3](../../bellman-calculus/catalogues/operators.md#forward-builders-measure-side). A method realizes its object through its [handler](../../wiki/handler.md), the routine that carries the method out, and an adapter, which converts the stage's objects into the routine's representation and converts its results back.

**defined in** links to the line of `packages/bellman/bellman/stage/method_table.py` in the repository `econ-ark/bellman` that defines the method type's row of `METHOD_TYPES`; the module's docstring names this page in return. **read from** names the module under `packages/bellman/bellman/`, the table and the key.

A methods file that names a tag absent from the table is refused, and so is an entry that places a method at a kind of place its row does not admit, omits a required setting, or writes a setting the row does not name without naming a handler that reads it; each refusal is under the rule `method-attachment` of [Refusals](refusals.md), except that `!Cartesian` written as a method, the fields of a grid written without the setting `grid`, and a grid written at the policy builder's Evaluation under `!egm` are refused under `grid-kind-as-method`, `grid-without-kind` and `grid-under-egm`. Configuration checks the values of the settings, and a value of the wrong kind is refused under the rule `method-option-value`.

> [!note] Grids and the model's sets
> The settings `orders` and `bounds` describe a numerical grid: the number of points and the interval, coordinate by coordinate, at which a function is computed and between which it is interpolated. A representation and `!egm` write them beside the setting `grid`, which names the grid's kind; `!vfi`, `!histogram` and `!root-find` write them alone. Changing them changes the approximation and leaves the model as it was. A finite set of alternatives the household chooses from is part of the model and is declared in the stage file.
