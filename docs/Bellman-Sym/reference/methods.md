# Method types

> [!summary]
> A **method type** is a numerical method that a methods file can type at a place of a stage, such as `!egm` or `!gauss_hermite`. The table lists every method type the package defines, one row each: the entry a methods file writes, the kinds of place at which the method may stand, the keyword arguments the package reads, the perch on whose states its grid lies, the object of the [Bellman calculus](../../wiki/bellman_calculus.md) it realizes, and the line of the package that defines it. The table is printed from the package's method table, and an entry that names a method type absent from it is refused. The kind of grid, the four shapes of its factors and the spacing word stand in §3.

> [!info]- Relationship with other documents
> **Builds on** — [Methodization](../04-methodization.md): how a methods file types a method, a grid and a handler at a place of a stage and declares its settings.
> **Formal account** — [Methods](../../bellman-calculus/06-Methods.md): the method and the grid as components of an operator's signature; [Operators](../../bellman-calculus/catalogues/operators.md): the operations the methods realize.
> **See also** — [Expression forms](forms.md): the forms a stage file writes, among them the operators `E`, `argmax` and `solve` at which a method may be typed; [Refusals](refusals.md): the rules `method-admission`, `component-typed-twice`, `grid-coordinate`, `grid-setting-declared`, `grid-bounds` and `method-option-value`; the wiki entries [methods](../../wiki/methods.md) and [grid](../../wiki/grid.md).

## 1 Reading the table

Each row is one method type. **written** is the entry of a methods file that types the method at a place, `<place>.method : !word`, the place written as [Methodization](../04-methodization.md) §2 writes it, in the bracket of the block that holds the operator or at file level with the full path; a word the table writes with a hyphen, `!gauss-hermite`, is written in a methods file with an underscore, `!gauss_hermite`, and the package reads the two as one word.

**bound at** lists the kinds of place the method type admits, in the words `stage.places()` prints ([Methods and places](../API/stage/07-methods.md) §1):

- *builder*, a whole [builder](../../wiki/builder.md), named by the id of its [block](symbols-conventions.md#5-equations-and-nodes), such as `policy` or `cntn_to_dcsn`;
- *node*, a line marked `!node`, and *statement*, any other line with an id, both named `<block id>.<line id>`;
- *definition*, a function the stage file or a methods file defines, named as the file writes it, such as `𝑑𝑢𝑖𝑛𝑣`;
- *operator* and a head, the occurrences of that operator: in one line, `<block id>.<line id>.<head>`, in every line of a block, `<block id>.<head>`, or in every line of the stage, by the operator's name alone, `E_ψ_ξ`, an expectation being named by `E_` and the shocks it integrates ([Methodization](../04-methodization.md) §2). The head `evaluate` names the [Evaluation](operations.md#evaluation) that closes the policy builder or a backward value builder, where a representation of what the builder stores is typed, `policy.evaluate`, `cntn_to_dcsn.evaluate`, and each object such an Evaluation stores, `cntn_to_dcsn.evaluate[V]` and `cntn_to_dcsn.evaluate[D_{m_d}V]`, and the Evaluation of a line marked `!node`, `cntn_to_dcsn.risk_ce.evaluate`; `upper_env` names the upper envelope of a candidate line.

**keywords** lists the keyword arguments the package reads, each with the set its value lies in and whether the word requires it; `n_<shock>` stands for one keyword per shock the expectation at the place integrates, `!gauss_hermite(n_ψ=n_ψ_nodes, n_ξ=n_ξ_nodes)`. A keyword the row does not list is admitted and kept for the [handler](../../wiki/handler.md) that carries the method out, which reads it or refuses it. The value of a keyword is written as the name of a declared setting, so that its number stands in the settings file; configuration requires a value for every name a keyword argument writes ([Methodization](../04-methodization.md) §3.1).

**grid** names the perch whose states the method's grid covers where it reads one: for a representation and for value function iteration, the perch at which the function the place holds is defined; for the endogenous grid method, the continuation perch, on which its grid of savings lies and at which the policy builder reads its input. The grid is typed by its own entry at the place, `<place>.grid : !Cartesian(…)` (§3), or takes the default, the product over those states with no number supplied.

**brings lines** says whether the method is a solution method that brings lines, which stand in place of the stage file's lines at the operative level, the builders the stage computes with ([Methodization](../04-methodization.md) §5). **derivatives it evaluates** says, for a representation method, which derivatives of the represented function the representation evaluates: a block of the stage that reads the value as its continuation value, and its derivative by the term `D_{a}V[>]`, is served by the representation alone where no derivative line states that derivative, and the stage that reads it checks nothing against this column ([Trellises](../07-trellis.md) §2.1). The column is information about the representation; a derivative line, in the stage file or in the methods file, whose values the representation at the builder's Evaluation stores, is the other way the derivative of a value is evaluated, and the methods file types that representation at the Evaluation, `cntn_to_dcsn.evaluate` for the value and its stated derivative together, or `cntn_to_dcsn.evaluate[D_{m_d}V]` for the derivative alone. **condition** names the condition under which the method's lines give the policy the stage file's declared line defines, with its sentence; `stage.obligations()` lists it under that name, and the package does not check it.

**denotes** links to the section of [Appendix E.3](../../bellman-calculus/catalogues/operators.md) that defines the object the method realizes. That object is the one E.3 defines for the first operator in the row's **bound at** cell, so a method bound at two operators links only the section of the first of them. A method bound at no operator, such as `!deterministic`, `!histogram` or `!identity`, is bound on a whole builder; the method table names no operator for it, so its row links no section and shows a dash; E.3 defines the backward builders in [§2](../../bellman-calculus/catalogues/operators.md#backward-builders) and the forward builders in [§3](../../bellman-calculus/catalogues/operators.md#forward-builders-measure-side). A method is carried out by its [handler](../../wiki/handler.md), the routine the methods file names.

**defined in** links to the line of `packages/bellman/bellman/stage/method_table.py` in the repository `econ-ark/bellman` that defines the method type's row of `METHOD_TYPES`; the module's docstring names this page in return. **read from** names the module under `packages/bellman/bellman/`, the table and the key.

An entry that names a word absent from the table is refused (`syntax`), and so is a word typed at a place of a kind its row does not admit (`method-admission`), one component written twice with different content (`declared-twice`) or typed at one place by two paths (`component-typed-twice`), and a typing of the derivative operator `D` (`no-method-for-derivative`); a keyword the row does not list is admitted and recorded for the handler. Configuration checks the values: a keyword's value outside the set its row names is refused under `method-option-value`, and a grid's bounds out of order, outside the declared set or with a count below two under `grid-bounds` ([Refusals](refusals.md)).

## 3 The grid

A method that reads a grid takes it from the grid entry of its place, `<place>.grid : !Cartesian(…)`, a typing beside the method's ([Methodization](../04-methodization.md) §3.2). The one kind is `!Cartesian`, the product of one set of points for each coordinate of the function the place holds, each factor keyed by the coordinate's name. A factor takes one of four shapes, the first with an optional spacing word, read from the package's grammar:

| Shape | Written | Meaning |
|---|---|---|
| spaced | `a=(a_min, a_max, n_a)` | `n_a` evenly spaced points from `a_min` to `a_max`, each a declared setting |
| spaced, with a spacing word | `a=(a_min, a_max, n_a, !expmult)` | `n_a` points from `a_min` to `a_max`, spaced as the word names, with keyword arguments where the spacing has a parameter, `!expmult(nest=grid_phi)`, each argument a declared setting |
| listed | `m=M_nodes` | the points of a node set: a setting the methods file declares and the settings file values by the list of its points, or a set the stage defines by its members |
| quadrature | `ν=E_ν` | the quadrature nodes of the expectation operator `E_ν`, for a coordinate represented on a shock |
| feasible | `c=(Γ_c, n_c)` | `n_c` points of the feasible set `Γ_c` of a control, for a method that searches over the control |

The spacing word the applications write is `!expmult`, a multi-exponential spacing, with its points denser near the lower bound, whose nesting factor is a keyword argument where the handler takes one; the package reads the keyword arguments of a spacing word as declared settings and checks the word itself nowhere, since the handler that builds the grid reads it. A factor that writes a number, or names a setting no methods file declares, is refused under `grid-setting-declared`. A factor keyed by a name that is no coordinate of the function at the place, a quadrature factor for a name that is no shock, a feasible factor for a name that is no control, and a grid written at a place whose method reads none are refused under `grid-coordinate`. A place without a grid entry, and a coordinate that no factor names, take the default, the product over the states of the perch the method's row names, with no number supplied.

> [!note] Grids and the model's sets
> A grid is a numerical object, the finite set of points at which a function is computed and between which it is interpolated. Changing it changes the approximation and leaves the model as it was. A finite set of alternatives the household chooses from is part of the model and is declared in the stage file, and the scalars that define it are parameters.
