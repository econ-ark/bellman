# Perch and information set

A **perch** is one of the three information contexts within a [[stage]]: **arrival**, **decision**, and **continuation**. The abbreviation **ADC** refers to this Arrival–Decision–Continuation ordering. A perch describes what is known, not an endpoint of a numerical [[operator]] or a separate calendar date.

## Information and state coordinates

In a probabilistic model, an information set can be represented by a sigma-algebra: a collection of events whose occurrence can be determined from the available information. A [[field]] measurable with respect to that sigma-algebra is a quantity determined by that information. The state vector need not record everything the household remembers. Using it as the argument of a value function requires a separate sufficiency condition.

For example, beginning assets are known before an income draw, resources are available when consumption is chosen, and savings are available for continuation. A transition that compresses assets and income into resources can discard information. Nested information contexts therefore do not imply that the sigma-algebras generated by the chosen state coordinates are nested.

## Written marks and declarations

`V[<]` requests arrival value; `V[>]` requests continuation value. A bare `V` or `V[~]` denotes decision value when its declaration and expression context establish that reading. Bare names in general are resolved from declarations and context; they are not all decision fields.

A [block](../Bellman-Sym/01-stage.md#3-builder-blocks) header states the contexts of its ordinary state and value coordinates. A control retains its decision role when listed as an argument beside continuation inputs. A shock used by a transition is not thereby known at the input perch. Its conditional distribution, scope, and use determine which uncertainty is integrated out.

Perch marks do not invert transitions, infer missing state sufficiency, or make an unobserved shock observable. [[branch|Branch]] labels distinguish alternatives within the continuation interface; they do not add a fourth perch. [Perch tagging rules](../Bellman-Sym/appendices/13-perch-tagging-rules.md) gives the precise syntax and examples.
